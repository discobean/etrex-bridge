eTrex Bridge

Direct USB mass-storage access to a Garmin eTrex 30x via the File System Access API.

This browser can't do it

The File System Access API's showDirectoryPicker() is Chromium-only (Chrome, Edge, Opera, Brave, Arc). Firefox and Safari implement only the origin-private filesystem, which is a sandbox inside the browser profile — it cannot reach a mounted USB volume. The page must also be served from https:// or http://localhost; file:// has an opaque origin and the API is not exposed there.

Device

Plug the eTrex in and wait for the volumes to mount. It presents two: GARMIN (internal, ~3.7 GB) and the microSD card. Pick one below. There is no plug-in event for mass storage and volumes can't be enumerated, so a click is required once per session.

Export this area as a Garmin Custom Map (KMZ)

Writes the basemap imagery for this track's extent to /Garmin/CustomMaps/ as a KMZ — JPEG tiles plus a KML GroundOverlay georeferencing each one. This is the only way the eTrex will display raster imagery. It is an overlay, not a routable map.

Custom maps stop drawing once you zoom out past roughly a 300 m scale. Exporting several zoom levels ships the same ground at coarser resolutions too, so the device has something it can still render as you zoom out. Three levels costs only about a third more tiles than one.

Transfer

Upload GPX → /Garmin/GPX/

Validated as well-formed XML with a <gpx> root before anything is written. Filenames are checked against /^[A-Za-z0-9 ._-]{1,64}\.gpx$/i.

Install map → /Garmin/gmapsupp.img

Streamed chunk-by-chunk — a 1 GB+ image is never held in memory. This replaces the map currently on the device.
